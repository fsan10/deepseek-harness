# 差评汇总分析

## 网页使用

启动客服后台，打开 `http://localhost:3000/reviews` 或左侧“差评汇总分析”。

1. 首次使用，在“采集设置 → 店铺配置”点击“同步店铺”，逐店配置采集范围。仅同步或登录时需要 Cloak Login 运行并开启本机 MCP。
2. 逐店选择，点击“登录并保存会话”。系统在手动登录或会话失效后自动恢复登录时连接真实 profile，复用共享登录恢复，并通过店铺信息 API 核对身份。验证码、短信或二次验证由人工处理，之后再次点击登录。
3. 会话按 profile 使用 Windows 当前用户 DPAPI 加密保存。保存成功后，可以关闭店铺浏览器；自动恢复登录时需保持 Cloak Login 可用。采集、商品补全和状态检查使用独立 HTTP，不在页面执行 fetch，不操作评价或订单 DOM。
4. 选择单店或全部在营店铺和日期，点击“开始采集”。默认昨天，每天覆盖北京时间 00:00:00–23:59:59；截止日期不能晚于昨天，单次最多 366 天。
5. 在采集记录查看进度。会话失效后自动重新登录、提取新 Cookie 并重试原采集。登录遇验证码或滑块等验证才群内通知人工；完成验证后自动继续，等待超过 5 分钟才另发登录失败通知。成功及无数据店铺保留进度。
6. 按店铺、日期、等级及搜索字段筛选。“按差评优先”可切换差评优先与评价时间倒序，差评优先时同等级仍按时间倒序；Excel 沿用当前筛选与排序，包含全部结果，不限当前页。超过 50000 条需缩小范围。分页最多显示 5 个数字页码，固定前三页和末两页，中间省略，支持更改每页条数和输入页码后按回车或移开焦点跳转。
7. 可设置 1–365 天的采集频率、回溯天数、北京时间执行时刻和 1–1440 分钟的登录检查间隔，默认 5 分钟。定时采集初始关闭，登录检查独立于定时采集开关。「店铺配置」抽屉可逐店关闭「自动检查登录状态」，启用中的店铺默认开启；关闭后仍可手动检查，采集时失效仍自动登录并继续原任务。需保持客服服务运行，不创建 Windows 计划任务。
8. “评价采集”和“采集设置 → 服务状态”的“查看采集服务日志”展示当前服务心跳、已保存的任务与逐店结果、最近登录检查。任务可展开并分页查看，支持手动刷新。“定时采集 → 查看运行日志”仅展示定时任务。日志来自数据库中保存的状态和执行说明，不是 Python 标准输出；查看日志不会创建或重试采集任务。

店铺 API 轮询确认登录有效性；失效时自动调用统一登录入口，更新会话后继续原操作；平台权限、风控或身份异常单独处理。网络失败显示检查失败，不当成登录失效。轮询在采集队列空闲时逐店执行，间隔是每店最短检查间隔；采集中会优先处理任务，每店采集前另行核验身份。网页提示和 CLI JSON 保留恢复动作；群通知由共用飞书配置控制，普通会话失效不立即通知人工。

定时任务从上次完整采集后补齐日期，包含未完成定时任务的日期；停机逾期会在恢复后执行。长范围拆分为不重叠的 30 天窗口，每页 20 条。

## 统一 CLI

使用 kefu 自己的虚拟环境；CLI 自动读取未提交的 `.env.local`，环境变量优先。所有命令输出一个 JSON 信封 `{ok,data,error,hints}`，普通日志写 stderr；成功退出码 0，失败为 1。`error` 包含 `code/message/recoverable/recovery_action`。

```powershell
# 查看实际支持的平台和命令契约
.\scripts\commerce.ps1 platforms
.\scripts\commerce.ps1 schema

# 首次发现店铺；此步骤需要 Cloak Login
.\scripts\commerce.ps1 --platform douyin profiles --refresh

# 唯一使用真实浏览器的认证命令
.\scripts\commerce.ps1 --platform douyin auth login --profile "DY-抖音-MOCK冲饮旗舰店"

# 以下命令优先使用独立 HTTP；会话失效时自动登录恢复
.\scripts\commerce.ps1 auth status --profile "DY-抖音-MOCK冲饮旗舰店"
.\scripts\commerce.ps1 auth status --all
.\scripts\commerce.ps1 reviews fetch --profile "DY-抖音-MOCK冲饮旗舰店" --from 2026-10-20 --to 2026-10-20
.\scripts\commerce.ps1 reviews collect --profile "DY-抖音-MOCK冲饮旗舰店" --from 2026-10-20 --to 2026-10-20
.\scripts\commerce.ps1 reviews status
.\scripts\commerce.ps1 reviews retry --run-id "<任务ID>"
.\scripts\commerce.ps1 auth logout --profile "DY-抖音-MOCK冲饮旗舰店"
```

也可执行 `.\.venv\Scripts\python.exe -m automation.commerce_cli ...`。`fetch` 直接返回评价，不写入评价业务表；认证状态与更新后的加密 Cookie 仍会保存。`collect` 仅加入持久队列，由客服服务的 worker 执行，不会自行启动网页服务。省略店铺时对所有已同步在营店铺建任务；省略日期使用默认回溯范围，`fetch` 默认昨天。`profiles` 不加 `--refresh` 时读取本地缓存。

当前平台注册表只实现 `douyin`（别名“抖音”）。其他平台返回 `NOT_SUPPORTED`，后续可沿用相同认证、命令信封和任务核心接入平台适配器。网页的同步、认证、创建任务及重试均调用这个 CLI 核心。

## 范围和口径

- 仅发现 `DY-抖音` 前缀。`DY-抖音-MOCK吉饮咖啡专卖店` 及备注中对应关店店铺默认停用；显式启用后按店铺配置中的勾选范围恢复采集，普通同步不覆盖人工启停。
- 公司、店铺优先读取备注 `platform=抖音;company=...;shop=...`。店铺名缺失时从店铺 API 补足，公司不猜测。实际身份与备注不一致即停止，禁止混用会话。
- 中评、差评分开请求，内容为“有内容”，评价状态、回复状态均为“全部”，不限定计入体验分。两种等级总数均为 0 才记录“无中差评”。分页、总数、结构或范围异常均为失败。
- 以 `(profile_id, comment_id)` 防重。评价接口缺少编码时，用订单 API 按商品单号、产品 ID 和必要的规格匹配，不取订单第一项或赠品编码。无法唯一匹配显示“待核对”，未配置显示“商家未设置”。
- 关键词来自平台标签及文本匹配，可多标签，不代表人工认定原因或差评率。关键词搜索也搜索正文。
- 订单号、产品 ID、规格 ID 使用字符串；Excel 按文本写入，评价不会解释成公式。旧日报、体验分和接待量数据不受影响。

## HTTP 与认证边界

以下接口来自开发阶段网页监听，正式执行使用 `httpx.AsyncClient` 携带独立会话直接请求官方 HTTPS 域名；不启动或连接业务浏览器，不导航概况、明细或订单页，不依赖页面安全 SDK。

| 用途 | 方法和路径 | 参数 |
| --- | --- | --- |
| 店铺身份及登录检查 | GET `/center/qualification/shop/info` | `version=0, appid=1, _bid=fxg_admin` |
| 评价明细 | GET `/product/tcomment/commentList` | `rank=2` 中评、`rank=1` 差评；`content_search=1,status_filter=0,reply_search=0,appeal_search=0,count_ecology_score_filter=0`；`comment_time_from/to` 秒级时间戳；`page` 从 0 开始、`pageSize=20,appid=1` |
| 商品编码补全 | GET `/api/order/orderDetail` | `order_id=shop_order_id`，匹配 `data.product.sku` 及 `merchant_sku_code` |

服务端 Cookie 更新会重新加密保存。三类采集共用 `data/collection-auth/<profile_id>.enc` 中按店铺隔离的会话，已被 Git 忽略；只能由同一 Windows 用户解密，不支持降级明文或跨用户直接复制使用。首次读取会自动迁移该账号原评论或指标目录中最近保存的加密会话。数据库只保存认证状态、提示、检查时间和店铺名，不保存 Cookie。会话有效期由平台决定，不保证永久有效，也不绕过验证或平台限制。

共享源码只在手动或自动登录、发现 profile 或建立登录互斥锁时导入，不修改 `mock_coffice`：

- `ReverseAPI/Formal_Script/profile_cdp.py`：精确匹配并复用或启动 profile。
- `scripts/auto_download/playwright/douyin_login.py`：首页登录、凭据恢复和人工异常处理。
- `scripts/auto_download/run_all_platform_downloads.py` 的 `ControllerRunLock`：登录与报表共享浏览器锁。独立 HTTP 任务不获取该锁，报表任务不阻塞已认证会话的采集。

仅关闭本次登录自行创建且无人工异常的标签页/profile，用户原有浏览器保留。登录失效自动调用统一认证入口；验证码或滑块通知人工后等待继续，权限、频率限制及身份异常单独处理。三类采集共用串行队列，默认体验分、评论、接待量，可在采集计划表中拖动排序后保存，当前任务不被抢占。

## 运行配置

首次安装或依赖变更后运行 `powershell -ExecutionPolicy Bypass -File scripts\setup-reviews.ps1`。使用本项目 Python 3.12 虚拟环境，无需下载 Playwright 浏览器；仅登录连接 Cloak 浏览器。Windows 当前版本的会话加密依赖 DPAPI。

`.env.local` 可配置以下路径，凭据不填入该文件：

```dotenv
MOCK_COFFICE_ROOT=D:\fsan10\mock_coffice
# 默认本项目 .venv；共享目录不用于选择解释器
# REVIEWS_PYTHON=D:\fsan10\kefu\.venv\Scripts\python.exe
# COLLECTION_AUTH_DIR=D:\fsan10\kefu\data\collection-auth
```

同步/CLI/Excel 使用本项目 `python.exe`，常驻 worker 使用本项目 `pythonw.exe` 静默运行。网页退出会取消进行中的 worker 和 CLI 操作。跨进程 worker 锁及 SQLite 持久队列防止重复执行，进程中断后可重试未完成店铺。运行时数据和凭据不会提交 Git。

更新代码后手动执行 `npm run build`，再运行 `scripts/start-local.ps1`。已有服务需先由使用者正常关闭。不要在旧 worker 正在执行任务时切换版本。

## 本地 API

| 路径 | 用途 |
| --- | --- |
| GET `/api/reviews` | 列表及汇总，支持 `from/to/shop/level/field/query/page/pageSize/sort`；`sort=latest`（默认）或 `negative_first` |
| POST `/api/reviews/collect` | `{from,to,profileIds:[]}` 入队；`{retryId}` 重试未完成店铺 |
| POST `/api/reviews/auth` | `{action:"login"或"status",profileId}`，显式登录/独立 HTTP 检查 |
| GET `/api/reviews/runs` | 最近任务、店铺进度、认证状态及 worker 心跳 |
| GET `/api/reviews/logs` | 已保存的任务记录及服务状态；`kind=service`（默认）或 `scheduled`，`page` 分页（每页 10 次任务），历史连接与鉴权信息脱敏 |
| GET/POST `/api/reviews/profiles` | 读取缓存/同步店铺清单 |
| GET/PUT `/api/reviews/settings` | `enabled,frequency_days,lookback_days,run_at,auth_poll_minutes` |
| GET `/api/reviews/export` | 当前筛选全部结果导出 Excel |

写操作使用同源 JSON。后台适用本机或可信局域网。登录过期、权限、网络失败等通过页面和 CLI 明确提示。
