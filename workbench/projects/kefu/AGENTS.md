# AGENTS.md

## 项目基础信息

- 本项目是客服部数据台，提供接待量分析、店铺体验分、每日指标管理、自动化导入和抖音差评汇总分析。
- 使用 Next.js、React、TypeScript 和 SQLite，在 Windows 本机或可信局域网内运行。
- 运行时数据库默认是 `data/kefu.sqlite`，可由 `KEFU_DB_PATH` 配置；数据库连接与初始化入口是 `db/local.ts`。
- `app/` 存放页面和 API，`db/reporting-config.ts` 维护店铺范围及指标口径，`automation/` 存放 Python 导入客户端和评价采集器。
- `db/schema.ts` 维护日报相关表定义，`drizzle/0000_kefu_initial.sql` 用于首次初始化，`db/reviews.sql` 维护差评相关表的幂等建表脚本。
- 修改前核对当前源码、数据库结构和运行状态，不以历史截图、文件名或旧测试结果代替当前事实。

## 环境搭建与开发流程

- 使用 Node.js 22.13 或更高版本、Python 3.12，以及本项目 `package-lock.json` 和 `requirements-reviews.txt` 管理的依赖。
- Python 命令必须显式使用本项目 `.venv\Scripts\python.exe`，优先通过 `-m` 调用模块；不得借用其他项目的虚拟环境。
- 虚拟环境尚未创建时，仅初始化步骤可以使用系统 Python 执行 `-m venv .venv`；创建后安装依赖和执行脚本均使用本项目解释器。
- Windows 常驻采集器使用本项目 `.venv\Scripts\pythonw.exe`；同步店铺、Excel 导出及测试使用本项目 `python.exe`。子进程须设置正确的项目工作目录并静默启动，不创建独立控制台窗口。
- `.venv/`、`node_modules/`、构建产物、数据库和临时文件不得提交 Git，保持 `.gitignore` 对这些内容的排除。
- 初始化使用 `scripts/setup-local.ps1`；仅初始化采集环境使用 `scripts/setup-reviews.ps1`。正式服务由用户运行 `scripts/start-local.ps1` 启动。
- 运行配置优先复用项目根目录未提交的 `.env.local`。Next.js 自动加载该文件；独立脚本需要配置时，应明确使用配置文件或仅向当前子进程注入必要变量。
- `MOCK_COFFICE_ROOT` 仅用于复用 mock_coffice 的 profile 连接、登录与人工异常处理代码，不用于选择 Python 环境。涉及共享代码时先核对调用路径和影响范围，不顺带改动其他项目。
- 保留工作区已有的未提交修改，只处理当前任务涉及的内容；未收到要求时不提交、推送或创建 PR。

## 业务数据与接口规范

- 店铺身份按 `(platform, name, kind)` 精确区分，保留用户指定的店铺名称、大小写和业务字段；不得凭相似名称合并店铺或覆盖历史数据。
- 店铺及指标的有效范围以 `db/reporting-config.ts` 为准，停用范围和历史记录分别处理，不能通过删除历史数据来隐藏停用店铺。
- 业务日期、评价时间、采集时间和任务执行时间分别保存；日期计算及默认范围使用北京时间 `Asia/Shanghai`。
- 指标名称、单位、百分比换算、比较条件和缺失值含义必须保持一致；缺少数据不得直接当成数值 0。
- 批量导入沿用 `/api/import` 的鉴权、字段校验和指标规范化逻辑；修改导入契约时同步更新 `API_IMPORT.md` 和相关调用示例。
- 数据库写入使用事务、参数化 SQL、唯一约束和外键校验；初始化、迁移和重复导入须可安全重试，不覆盖已有业务数据。
- 新增功能的数据表与现有日报、接待量、体验分数据保持明确边界，不跨功能修改历史记录来修正展示结果。

## 差评采集规范

- 评论当前只采集抖音，以名称前缀 `DY-抖音` 发现 profile；`DY-抖音-MOCK吉饮咖啡专卖店` 及备注中的已关店店铺默认停用。店铺配置中显式启用后，按该店铺勾选的范围恢复采集；同步不得覆盖人工启停和采集范围，普通采集不得自动启用停用店铺。
- 店铺和公司优先读取 profile 备注，通过店铺信息 WebAPI 核对实际登录店铺；身份不一致时停止该店铺，不能猜测或混用归属。
- 真实浏览器只用于首次登录、重新登录与会话提取，登录恢复沿用共享模块。支持用户手动点击登录；独立 HTTP 明确检测到会话失效时，自动调用同一登录入口、更新加密会话并继续原任务。按 profile 使用 Windows 当前用户 DPAPI 加密保存会话，禁止明文或输出凭据。
- 正式业务采集、商品信息补全和登录状态轮询必须使用独立 HTTP WebAPI，不依赖浏览器、CDP、页面 fetch 或 DOM。会话失效先自动恢复，登录中遇验证码、滑块或二次验证才通知人工；人工超过 5 分钟未处理时再通知登录失败。网络、接口结构、权限和店铺身份错误不得误判成会话失效或盲目重登；开发阶段允许为监听请求操作页面。
- 中评、差评分开查询，评价内容为“有内容”，评价状态和回复状态保持“全部”；默认采集昨天，支持自定义日期范围和默认回溯天数。
- 两种等级均无数据时记录“无中差评”并继续下一店铺；接口失败、返回结构变化、总数异常或提前空页必须记录为失败，不能冒充零数据或成功。
- 评价数据以 `(profile_id, comment_id)` 防重。商品编码优先使用评价接口，缺失时通过订单接口按商品单号、产品 ID 和规格匹配，不能取订单第一件商品或把赠品编码当成正品编码。
- 订单号、产品 ID、规格 ID 使用字符串，Excel 导出按文本写入并防止将评价内容解释为公式；导出结果包含当前筛选的全部数据。
- 登录失效、验证码、短信或二次验证、权限和店铺身份异常复用共享人工处理流程，保留对应 profile 等待处理，不自动绕过验证。
- 保留已成功店铺的任务进度，重试只处理未完成店铺。三类采集共用跨进程执行锁，正在执行的任务不被抢占，到期任务按计划表中已保存顺序串行执行，默认体验分、评论、接待量。手动或自动登录与报表任务共享浏览器互斥锁，独立 HTTP 采集无需浏览器锁。不重置其他任务的锁或检查点。
- 仅停止本次采集自行启动且无人工异常的 profile，保留用户原已运行的浏览器。网页服务退出时，采集器应及时取消正在执行或等待人工的任务并退出，避免残留进程。

## 测试规范

- 根据改动范围执行必要检查。纯文档修改检查内容、链接和差异即可，不为此启动服务、浏览器、采集任务或写入数据库。
- TypeScript、页面或 API 变更执行对应的静态检查和必要验证；Python 采集、队列或导出逻辑变更执行相关回归测试。
- 常用检查命令如下，按实际改动选择：

  ```powershell
  npm run lint
  npm run build
  & .\.venv\Scripts\python.exe -m unittest discover -s tests -p test_reviews.py -v
  & .\.venv\Scripts\python.exe -m unittest discover -s tests -p test_reviews_http.py -v
  node --experimental-strip-types --test tests/review-runtime.test.mjs
  ```

- 自动化测试优先使用临时 SQLite 数据库和测试目录；确需访问真实业务数据时先明确范围，不能向正式数据库写入假数据。
- 区分静态检查、单元测试、接口验证和真实浏览器采集验收，交付时说明实际完成的验证，不以构建成功代替实采成功。
- **每次修改并完成测试后，必须关闭开发者或 AI 助手自己启动的全部终端、开发/生产服务、测试服务及其采集子进程，确认释放本次占用的端口后再交付。**
- 测试结束不得遗留自己启动的后台服务、守护进程或自动重启任务，不得在清理后又替用户启动正式服务；正式项目由用户手动启动，避免端口占用或旧服务继续提供旧页面。
- 启动验证服务前记录进程、工作目录和端口，清理时核对进程归属及子进程。只关闭能够确认由自己启动的进程，不能按进程名称或端口批量停止用户的服务和终端。
- 测试结束清理本次产生的临时数据库、测试记录、临时导出和抓包文件；不得为清理测试痕迹删除真实业务数据、生产审计记录或用户原有文件。
