# 01 · 现状诊断

> 诊断基于 2026-10-22 的工作区源码与运行结构，不以历史截图或旧文档为准。本轮未运行采集任务、未写入数据库。

## 1. 现有页面清单

表面上有 5 个「页面」，实际只有 2 个路由、1 个主组件。

| 入口 | 实际渲染 | 用户看到的功能 | 取数 |
| --- | --- | --- | --- |
| `/` | `Dashboard`（`initialView="overview"`） | 经营总览 | `GET /api/dashboard?view=overview` |
| 侧栏「接待量分析」 | 同一 `Dashboard` 内的条件块 | 平台筛选、KPI、30 天趋势、店铺明细 | `?view=reception` |
| 侧栏「店铺体验分」 | 同上 | 店铺选择、5 张评分卡、指标明细、趋势、全店对比 | `?view=store-score` |
| 侧栏「数据管理」 | 同上 | 类型切换、筛选、记录 CRUD、批量导入说明 | `?view=data-management` |
| `/reviews` 或侧栏「差评分析」 | 同一个 `Dashboard`，`initialView="reviews"` | 采集配置、筛选、KPI、关键词、明细、商品排行、采集记录 | `/api/reviews*`（独立一套） |

证据：
- `app/page.tsx:1-5`、`app/reviews/page.tsx:1-5` 都渲染 `Dashboard`。
- `app/Dashboard.tsx:6` 用 `View` 联合类型表示 5 个视图；`:324` 起是唯一主组件。
- `app/Dashboard.tsx:479` 差评页是 `view === "reviews"` 时挂载 `ReviewAnalytics`；其余 4 个视图是 `:484 / :501 / :514 / :525` 的条件块。

## 2. 功能分布（按用户意图归类）

| 意图 | 现在散落在 | 具体功能 |
| --- | --- | --- |
| 看结果 | 总览、接待量、体验分、差评 | KPI、趋势、排行、异常、明细 |
| 找原因 | 接待量、体验分、差评 | 平台筛选、店铺筛选、关键词、商品排行 |
| 补数据 | 数据管理、差评页内「采集与定时配置」 | 新增/编辑/删除、立即采集、同步店铺、定时设置、重试 |
| 接数据 | 数据管理里的「批量导入」弹窗 | API 地址、鉴权、批量上限、模板说明 |
| 导数据 | 顶栏「导出」、差评页「导出 Excel」、表头「导出当前筛选」 | CSV / XLSX 三种入口、三种作用域 |

结论：**同一件事有多个入口，不同的事挤在同一页**。用户无法通过导航判断「我现在该去哪」。

## 3. 八类问题与证据

### P0-1 路由缺失：5 个视图共用一个组件，URL 不承载状态

- `Dashboard.tsx:325` 视图是 `useState`；`switchView`（`:389-395`）只改状态，不改 URL。
- 后果：刷新回到总览；浏览器后退无效；无法把「某平台、某日期」的链接发给同事；`/reviews` 只是换了个初始值，和 `/` 共用同一套状态。
- 影响：所有「分享、回到上次位置、多标签对照」的诉求都无法满足。

### P0-2 取数契约按视图分裂，一个 payload 装四种页面

- `app/api/dashboard/route.ts:434-445` 用 `view` 参数在一个端点里分派 4 个查询函数。
- 客户端 `DashboardData`（`Dashboard.tsx:10-31`）有 17 个可选字段；`rows` 在接待量是店铺明细、在数据管理是记录列表；`trend` 在总览是 7 天、在接待量是 30 天；`latestDate` 在数据管理是「当前页第一条的日期」。
- `load()`（`:343-382`）把当前页面的筛选状态一股脑带进请求，再按视图挑参数；新增一个视图就要同时改端点、类型和 `load`。
- 影响：改一个页面容易碰坏另一个；类型系统无法帮助发现字段误用。

### P0-3 页面职责混杂：一个页面承担三种意图

- 差评页（`ReviewAnalytics.tsx:158-210`）同时是：分析看板（KPI/关键词/明细/商品排行）、采集控制台（立即采集/同步店铺/定时设置）、任务监控（采集记录/重试）。
- 数据维护页（`Dashboard.tsx:525-530`）同时是：数据浏览、记录 CRUD、导入接入说明（`:535` 的弹窗）。
- 影响：首屏被配置表单占满；分析与运维互相干扰；权限、出错处理、刷新频率都不同却绑在一起。

### P1-4 组件各自为政，复用只停留在「看起来像」

- KPI 卡有 4 套写法：`Dashboard.tsx:487-490`、`:504-507`、`:516`（评分卡）、`ReviewAnalytics.tsx:162-167`。
- 表格有 4 套：接待量 `:510`、指标 `:518`、数据 `:528`、差评 `ReviewAnalytics.tsx:195`；分页有 2 套（`:529` vs `:204`）。
- `Panel` 只在 `Dashboard` 用，`ReviewAnalytics` 直接写 `.panel` + `<h3>`（`:169 / :186 / :209`），标题层级（h2/h3）和间距都不同。
- 反馈有 2 套：`toast`（`:480`）与 `review-notice`（`ReviewAnalytics.tsx:161`）；错误条一个带「重试」（`:481`），一个只带「关闭」（`:160`）。
- 影响：同一个系统里，卡片高度、标题字号、分页位置、错误处理方式都不一致；改一次样式要改 4 处。

### P1-5 日期有 3 套实现、5 种语义

- 实现：`todayChina/shiftDate`（`Dashboard.tsx:67-75`）、`dateFromValue/dateValue/calendarDays`（`:174-193`）、`day()`（`ReviewAnalytics.tsx:22-26`）；另有原生 `<input type="date">`（`Dashboard.tsx:534`、`ReviewAnalytics.tsx:172/188`）。
- 语义混用：「数据日」（`Dashboard.tsx:485` 只读展示）、「今日/昨日」（KPI 文案）、「评价日期」（差评筛选）、「采集日期」（不得晚于昨天）、「执行时刻」（HH:mm）。
- `DateRangePicker` 只在数据管理出现（`:527`）；总览反而不给日期入口。
- 影响：用户不知道「今天」指业务日还是自然日；采集与分析共用一套日期文案，容易误操作。

### P1-6 指标口径在客户端二次实现

- `formatValue` / `isRisk` / `Status`（`Dashboard.tsx:89-124`）在浏览器里重新判断「达标/未达标」，而服务端 `api/dashboard/route.ts:208-212` 也有一套目标比较。
- 5 分制换百分比 `value <= 5.1 ? value / 5 * 100 : value` 在 `:495 / :516 / :521` 重复 3 次，魔数散落。
- 影响：口径调整要改两处；任何一处漏改都会出现「列表达标、卡片未达标」。

### P2-7 交互与可访问性缺口

- 侧栏是 `<button>` 而非链接（`:463`），无法新开标签；弹窗无焦点陷阱、无 Esc 关闭（`:534-535`）；`FancySelect` 只处理 ↑/↓/Esc（`:165-169`），没有 Enter/Home/End 与焦点管理；自绘日历无键盘路径。
- 加载态是整页 500px 的转圈（`:482`），一进页面所有区块一起消失；没有分区块骨架屏。

### P2-8 导出作用域不一致

- 顶栏「导出」（`:402-419`）按当前 `view` 猜导哪份数据：总览导出平台占比，数据管理只导出当前页 20 条。
- 差评页另有「导出 Excel」（`ReviewAnalytics.tsx:146-155`），导出全量筛选结果；表头又出现「导出当前筛选」。
- 影响：同名动作结果不同，用户无法预期。

## 4. 根因

1. **以「一个组件装下所有页面」代替路由**：视图状态、取数、筛选、弹窗全部堆在 `Dashboard`，页面边界消失。
2. **以数据表/接口为中心划分页面**：`view` 的取值来自查询函数，而不是用户任务，于是「采集配置」被塞进分析页，「导入说明」被塞进维护页。
3. **缺少共享层**：没有页面骨架、筛选条、数据面板、状态组件，只能复制粘贴，复制后各自演化。

## 5. 重构目标（可验证）

| 目标 | 验收方式 |
| --- | --- |
| 8 个独立路由，URL 可复现筛选 | 直接打开带参数的链接，页面状态一致；刷新不丢 |
| 单页组件 ≤ 220 行，只组合不实现 | 代码行数与依赖检查 |
| 页面级筛选 0 个原生 `input[type=date]` | 全局搜索 |
| 只有 1 套日期工具与 4 个日期组件 | 目录与引用检查 |
| 只有 1 套表格、1 套分页、1 套 KPI、1 套反馈 | 组件清单 |
| 每个页面 1 个主操作 | 设计走查 |
| 指标口径只在服务端计算一次 | 客户端不再出现目标比较与 5 分制换算 |
