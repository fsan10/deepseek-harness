# 03 · 日期组件使用规范

> 目标：把现在 3 套日期实现、5 种日期语义，收敛为 **4 种形态 + 1 套北京时间规则**。本规范是设计与实现共同遵守的口径，本轮不改代码。

## 1. 现状为什么必须统一

| 现状 | 位置 | 问题 |
| --- | --- | --- |
| `todayChina()` / `shiftDate()` | `app/Dashboard.tsx:67-75` | 用 `Intl` 取北京日期，但只服务于总览与导出文件名 |
| `dateFromValue()` / `dateValue()` / `calendarDays()` | `app/Dashboard.tsx:174-193` | 自绘日历的私有实现，只在 `DateRangePicker` 内可用 |
| `day(offset)` | `app/ReviewAnalytics.tsx:22-26` | 先取北京日期字符串，再拼 `T00:00:00Z` 用 UTC 加减，和上一套不是同一种算法 |
| 原生 `<input type="date">` | `Dashboard.tsx:534`、`ReviewAnalytics.tsx:172/188` | 浏览器 locale 决定显示格式；无快捷预设；无法限制到「昨天」；移动端与桌面端行为不一致 |
| 只读日期文本 | `Dashboard.tsx:485` | 总览没有日期入口，用户无法查看更早的数据日 |

语义混用更危险：KPI 写「今日总接待」，但实际取的是**最新数据日**；采集页写「开始日期」，边界却是**不得晚于昨天**；配置页的「执行时间」是时刻，不是日期。三者在界面上长得一样，用户只能靠猜。

## 2. 统一数据模型

```ts
// 只存字符串，不存 Date 对象，不跨层传时间戳
type DateString = `${number}-${number}-${number}`; // YYYY-MM-DD

type DateScope =
  | { kind: "data-date"; date: DateString | null }        // 系统推导，只读
  | { kind: "day"; date: DateString }                     // 单日
  | { kind: "range"; from: DateString; to: DateString; preset?: PresetKey }
  | { kind: "time"; time: `${number}:${number}` };        // HH:mm

type PresetKey = "yesterday" | "last7" | "last30" | "thisMonth" | "custom";
```

规则：
- 时区唯一：`Asia/Shanghai`。禁止 `new Date()` 直接取本地日期，禁止用 UTC 加减模拟北京日期。
- 存储唯一：`YYYY-MM-DD`；跨页、跨接口、写 URL 都用这个格式。
- 展示可缩短：表格 `2026-10-21`，图表轴 `10-21`，标题可写「10 月 21 日」，但**值不变**。
- 空值有语义：`null` 表示「未指定」，不是 `1970-01-01`，也不是「今天」。

## 3. 四种形态

### 3.1 单日 · `DateField`

```
┌──────────────────────────────┐
│ [日历]  2026-10-21        [▾] │  36px
└──────────────────────────────┘
```

- 用途：新增/编辑记录的业务日期；任何只需要一天的输入。
- 默认值：当前数据日；无数据时取今天。
- 边界：`max = 今天`；必填。
- 交互：点击展开单月日历；Esc 关闭；Enter 选中；焦点回到触发器。
- 不用于：页面级范围筛选（用 `DateRangeField`）。

### 3.2 范围 · `DateRangeField`

```
┌────────────────────────────────────┐
│ [日历] 10-01 ~ 10-21           [▾] │  36px
└────────────────────────────────────┘
  昨天   近 7 天   近 30 天   本月   自定义
```

- 用途：所有分析页与采集日期。
- 默认值：
  - 分析页：以**最近数据日**为终点，向前 6 天（总览/趋势）或 29 天（明细）。
  - 采集页：以**昨天**为终点，向前 `lookback_days - 1` 天。
- 边界：
  - 分析：`max = 今天`；无数据时明确提示，不画空图。
  - 采集：`max = 昨天`；未来日期不可选。
- 交互：
  - 打开时显示双月日历；先点开始、再点结束；若第二次点击早于开始，自动交换。
  - 悬停预览区间；点击预设立即应用并关闭。
  - 底部显示「YYYY-MM-DD 至 YYYY-MM-DD」，未完成选择时显示「请选择结束日期」。
  - Esc 关闭并还原上次值；「清空」只在允许空值的场景出现。
- 键盘：
  - 触发器 `Enter/Space` 打开，`Esc` 关闭，关闭后焦点回到触发器。
  - 日历内 `←/→` 移动一天，`↑/↓` 移动一周，`PageUp/PageDown` 切换月份，`Home/End` 跳到本周首尾，`Enter` 选中。
  - 每一天有可读标签（`aria-label="2026年10月21日，星期三"`），今天用 `aria-current="date"`。

### 3.3 只读 · `DataDateTag`

```
● 数据日 2026-10-21          查看更早数据
```

- 用途：总览、体验分等「以数据日为单位」的页面。
- 规则：**不可手选**。数据日由系统按「该范围内最大的 `report_date`」推导；需要更早数据时，走「查看更早数据」进入带范围的分析页或数据维护。
- 文案：`数据日 YYYY-MM-DD`；旁边可加「更新于 HH:mm」。
- 为什么不放日期选择器：如果数据日可以随便选，用户会以为没有数据是「筛选错了」，而不是「当天还没导入」。

### 3.4 时刻 · `TimeField`

```
┌──────────────────────────────┐
│ 09:00              北京时间  │  36px
└──────────────────────────────┘
```

- 用途：仅采集设置里的「执行时间」。
- 规则：24 小时制，`HH:mm`，`00:00–23:59`；不参与分析筛选。
- 不与日期混排：配置页的「频率（天）」和「时刻」分开两行，不要拼成「每隔 1 天 09:00」。

## 4. 默认值与边界总表

| 场景 | 组件 | 默认值 | 最小 | 最大 | 空值 |
| --- | --- | --- | --- | --- | --- |
| 总览数据日 | DataDateTag | 最新数据日 | — | 今天 | 显示「暂无数据」+ 去导入 |
| 接待量范围 | DateRangeField | 最近数据日往前 29 天 | 未限定 | 今天 | 不允许为空，回落到默认 |
| 体验分范围 | DateRangeField | 最近数据日往前 29 天 | 未限定 | 今天 | 同上 |
| 差评评价日期 | DateRangeField | 昨天（按回溯天数） | 未限定 | 昨天 | 不允许为空 |
| 采集日期 | DateRangeField | 昨天 | 未限定 | 昨天 | 不允许为空 |
| 记录日期 | DateField | 当前数据日 / 今天 | 未限定 | 今天 | 必填 |
| 数据维护筛选 | DateRangeField | 本月 1 日至今天 | 未限定 | 今天 | 允许为空 = 全部日期 |
| 执行时刻 | TimeField | 09:00 | 00:00 | 23:59 | 必填 |

> 待确认：分析页范围上限是否限制为 366 天。现有接口不限制，但过长范围会让 30 天窗口查询变慢；建议在 UI 上限制并提示。

## 5. 文案规范

| 场景 | 写法 | 不要写 |
| --- | --- | --- |
| 只读数据日 | 数据日 2026-10-21 | 今日、最新 |
| KPI 对比 | 较上个数据日 / 较前 7 天 | 较昨日（当数据日不是昨天时会误导） |
| 范围触发器 | 10-01 ~ 10-21 | 2026-10-01 至 2026-10-21（太长） |
| 采集边界 | 采集截止昨天 | 不能选今天 |
| 表格日期 | 2026-10-21 | 10-21（跨年时歧义） |
| 图表轴 | 10-21 | 2026-10-21（拥挤） |
| 错误 | 结束日期不能早于开始日期 | 日期无效 |

## 6. 禁用清单

- ❌ 页面级筛选直接使用 `<input type="date">`。
- ❌ 用两个 `DateField` 拼一个范围。
- ❌ 在顶栏放日期选择器（顶栏只放页面标题与动作）。
- ❌ 用「今天 / 昨天」作为存储值或 URL 参数。
- ❌ 在客户端用 `new Date()` 取「今天」再 `toISOString()` 截断（会得到 UTC 日期）。
- ❌ 空结果显示成 0 或空白图；必须区分「没有数据」与「筛选无匹配」。
- ❌ 同一个页面出现两种日期格式（如 `2026/10/21` 与 `2026-10-21` 混用）。

## 8. 验收用例

1. **跨零点**：服务器时间为 UTC 16:30（北京次日 00:30），`todayISO()` 返回北京的新日期。
2. **分析默认**：最新数据日为 10-21，今天为 10-22；打开接待量页默认范围为 09-22 ~ 10-21，且 KPI 文案写「较上个数据日」。
3. **采集边界**：今天为 10-22；采集日期最大只能选 10-21，手动输入 10-22 被拒绝并提示。
4. **范围纠正**：先点 10-21，再点 10-01，结果自动变为 10-01 ~ 10-21。
5. **清空**：数据维护筛选清空后显示全部日期；分析页不提供清空，避免空图。
6. **记录默认**：新增记录默认当前数据日；选择未来日期时保存按钮禁用并提示。
7. **键盘**：只用键盘可以完成「打开 → 选开始 → 选结束 → 关闭」，焦点不丢失。
8. **可访问性**：每个日期按钮有完整中文标签；今天与选中态可被读屏区分。
