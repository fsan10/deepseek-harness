# AGENTS.md

## 项目基础信息
- 本项目用于快速验证财务经营指标，并在 DataEase 中生成指标卡和图表。
- 数据库为 PostgreSQL `mock_coffice`，默认地址为 `192.168.77.111:5432`。
- 数据链路为 `ODS -> 指标专属DWD -> 平台专属DWS -> 指标专属ADS -> DataEase`。
- ODS 是字段分析和指标计算的唯一事实来源，不追求标准数仓或跨指标复用。
- 一个指标建设一套独立的 DWD、DWS、ADS、刷新 SQL 和 ETL。
- 公司店铺关系只维护在 `dim.dim_platform_shop_company`，ADS通过DIM生成公司维度。
- ODS明细只保存`batch_id`，批次店铺归属维护在`ods.ods_file_ingest_log`。
- 平台经营收支归属使用`operating_treatment`：收入、支出、不计入；增加或冲减沿用来源公式符号，不以分类名称推断。
- 收支分类未映射必须保留已确认的经营金额，分类显示“未映射”；清除、停用分类不得改变经营归属或总额。
- 来源性质待确认与分类未映射必须区分；提现、账户划转、仅核对和重复来源保留全部明细，来源防重及批次店铺校验继续执行。

## 环境搭建与开发流程
- 使用 Python 3.12、PostgreSQL、`psycopg2-binary`，`.xlsx`导入使用`openpyxl`。
- 执行 Python 相关命令时，统一使用项目虚拟环境 `.venv\Scripts\python.exe` 显式使用该解释器并通过 `-m` 调用，禁止使用裸 python 或 py -3.12。
- 数据库连接使用`PGHOST`、`PGPORT`、`PGDATABASE`、`PGUSER`、`PGPASSWORD`。
- ODS导入脚本位于`etl/<platform>/load_*_ods.py`，新批次必须传入标准`shop_code`。
- Loader必须先校验DIM，再写入标准平台、店铺和公司批次上下文。
- 新指标先使用`$explore-ods-data`探查真实ODS并确认口径。
- 口径确认后使用`$build-metric-pipeline`设计图表并实施完整指标链路。
- 公式、日期、状态、退款、店铺归属和展示维度确认前不得加工指标。
- DWD只选择和清洗指标字段，DWS执行平台口径，ADS只服务指定图表。
- DataEase只读取ADS，并通过公司、日期、平台筛选器联动指标和图表。
- SQL按职责存放：平台对象进`sql/<platform>/`，ADS进`sql/ads/`，DIM进`sql/dim/`，通用对象进`sql/common/`。
- 禁止在`sql/`根目录放SQL；新SQL使用全局递增序号，ETL显式列出完整相对路径。
- Playwright脚本位于`scripts/auto_download/playwright/`。仅当脚本改动改变面向使用者的功能、适用平台或报表、操作流程、CLI参数、依赖、输入输出、路径或使用示例时，才同步更新`README.md`。仅修复内部实现、选择器、等待、重试、兼容性或测试且不改变对外使用方式和行为时，无需更新`README.md`；不得把代码实现细节或普通修改记录写入`README.md`。

## 测试规范
- 刷新前校验ODS来源表、必需字段、数据量及全部来源批次店铺映射。
- 批次未映射或冲突时立即停止，不得静默丢弃或兜底。
- DWD校验最小粒度唯一、字段清洗和状态未提前筛选，并抽样核对至少5条。
- DWS校验筛选数量、主键唯一、组成金额和指标公式。
- ADS校验粒度唯一、日期范围、DWS汇总一致及未匹配公司数量。
- 新增表必须校验表注释和全部字段注释无遗漏。
- 测试结束后必须关闭本次启动的后端或开发服务进程，由用户自行重新启动，避免旧服务占用端口。
- 测试结束必须清除本次产生的全部数据（会话、登录尝试、审计日志、外键引用）必须硬删除，不得软删或残留。

## 代码规范
- SQL、Python、Markdown统一使用UTF-8，所有数据库对象显式指定schema。
- DWD、DWS、ADS字段使用英文`snake_case`，ODS保留平台源字段名。
- 所有建表SQL必须有表注释，每个字段必须逐一添加`COMMENT ON COLUMN`。
- 字段注释必须说明业务含义、来源、单位、枚举或计算口径。
- 金额使用`NUMERIC(18,2)`，业务日期使用`DATE`，审计时间使用`TIMESTAMPTZ`。
- 刷新SQL必须可重复执行。文件导入自动执行按标准平台、店铺和受影响业务月份的增量替换，来源快照与刷新范围必须冻结；全量`TRUNCATE + INSERT`仅允许人工创建，范围不明时停止，不得自动回退全量。
- ETL失败必须回滚，并输出各层行数、日期范围和指标汇总值。
- DWD必须通过`common.v_ingest_batch_shop_context`按`batch_id`获取标准店铺。
- 公司、店铺归属不得硬编码在指标SQL中。

## 操作边界与禁止行为
- 禁止修改、删除或覆盖ODS原始数据来修正指标结果。
- 禁止在DWD增加订单状态、售后状态等指标筛选。
- 禁止复用其他指标表，或为标准分层增加无关表和字段。
- 禁止把平台差异写入ADS，平台逻辑必须在对应DWD/DWS完成。
- 禁止在指标表维护公司店铺映射，映射变更只能修改DIM。
- 禁止以文件名、平台唯一店铺或静默`default`替代批次店铺参数。
- 禁止在用户未确认时推测或改变指标筛选条件。
- 密码、令牌、私钥、加密密钥、数据库连接串等敏感信息禁止写入源码、SQL、文档、示例配置的真实值、命令行参数、命令历史或 Git 提交；运行时优先从项目根目录未提交的`.env`加载，或由部署平台的 Secret/进程环境注入，`.env.example`只能放变量名和明显占位符。
- 除非用户明确要求，不得要求用户执行或替用户持久化写入 Windows 用户/系统环境变量（例如`$env:INITIAL_ADMIN_USERNAME=...`或`[Environment]::SetEnvironmentVariable(...)`）；需要临时进程变量时也不得把真实敏感值回显到聊天、日志或测试输出中。
- AI需要运行项目时，应优先复用`.env`并使用工具自身的`--env-file`/环境文件参数；若目标工具不自动读取`.env`，应明确说明作用域和加载方式，不能把设置用户环境变量作为默认方案。
