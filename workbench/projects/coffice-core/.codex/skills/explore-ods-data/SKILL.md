# ODS 数据探查

## 开始前

1. 定位包含本 Skill 的项目根目录。
2. 完整读取根目录 `AGENTS.md`。
3. 完整读取 `docs/ods_to_dws_to_ads_standard_flow.md`。
4. 将 ODS 建表 SQL、数据库真实数据和 `data/` 源文件视为事实来源，优先级依次为真实数据、源文件、DDL 注释。

## 职责边界

- 只进行读取、查询、抽样、统计和方案分析。
- 不创建或修改 SQL、ETL、表结构、映射和业务数据。
- 不替用户决定日期、状态、退款、符号、公司归属等业务口径。
- 发现业务口径不确定时，先计算候选结果，再向用户提问。
- 可发现的数据库事实必须自行探查，不得把字段位置、枚举值、空值率等问题抛给用户。

## 探查流程

### 1. 识别来源

- 根据平台和指标定位可能的订单、结算、资金、广告、银行等 ODS 表。
- 使用 `rg --files sql` 和 `rg` 递归搜索 `sql/<platform>/ods/`、ETL配置和源字段，不假设SQL位于根目录。
- 查询 `information_schema` 确认数据库中的真实表和字段。
- PowerShell 内联脚本查询中文字段时，使用 Unicode 转义和 `psycopg2.sql.Identifier`，或直接读取UTF-8 SQL文件，避免中文列名被替换为问号。
- 检查 `ods_file_ingest_log`、来源文件、Sheet、表头和导入日期。
- 按来源表统计ODS行与`batch_id`覆盖率，并检查批次的`shop_mapping_status`、标准店铺和DIM命中率。
- 对比源店铺ID/名称与批次上下文；不一致时标记`conflict`并询问用户，不自行决定优先级。
- 来源仅存在于 CSV/XLSX 时，读取文件结构和样例；不得修改源文件。

### 2. 确认最小粒度

- 统计总行数和候选主键去重数。
- 检查主订单、子订单、结算记录、资金流水或广告日记录之间的关系。
- 检查重复版本，确定最新记录选择规则。
- 判断金额是主订单级、子订单级、日级还是流水级，防止重复求和。

### 3. 分析指标字段

- 对公式中的每个字段记录来源表、原始字段、类型、样例和清洗规则。
- 统计空值、空字符串、横杠、文本前缀、百分号、货币符号和解析失败数量。
- 对费用类字段检查正负号含义、退款冲回和净额逻辑。
- 对优先级和兜底字段分别统计可用数量；不得因当前无缺失而省略已确认的兜底机制。
- 抽样核算至少 5 条记录，展示原值、清洗值和公式结果。

### 4. 分析日期与筛选

- 列出所有可用业务日期，统计为空数量、日期范围和跨日差异。
- 对订单状态、售后状态、结算类型、业务类型等字段列出完整枚举及数量。
- 对每个合理候选口径计算行数和指标总额。
- 不把“常见做法”当作用户已确认口径。

### 5. 分析展示维度

为每个候选维度输出来源、覆盖率、基数、关联方式和适合的图表：

- 财务公共维度：`stat_date`、`company_code/company_name`、平台。
- 业务维度：店铺、渠道、商品、达人、费用类型、订单类型等，仅在源数据真实支持时推荐。
- 公司维度必须从`batch_id -> common.v_ingest_batch_shop_context -> DIM`检查命中率；未命中数据不得静默删除。
- 高基数标识符不得直接推荐为领导看板筛选项。

默认展示建议是一张指标卡加一张图：时间序列优先折线图，分类比较优先条形图，构成分析优先堆叠图，排名优先降序条形图。建议必须基于已探查的维度质量。

### 6. 提问并锁定口径

- 只询问会改变指标结果、维度或图表设计的决策。
- 每次最多提出 3 个相关问题，推荐项放在前面。
- 问题必须带候选规则、当前数据结果和影响，例如不同状态过滤对应的金额差异。
- 可使用 `request_user_input` 时优先使用；用户未回答前不得进入指标加工。
- 将用户回答逐条写入口径确认结果，不保留模糊描述。

## 交付格式

输出一份“ODS 指标探查报告”，至少包含：

1. 平台、指标名称和业务目标。
2. ODS 来源表、源文件、最小粒度和当前数据范围。
3. 公式字段映射与清洗/兜底规则。
4. 日期口径候选及差异。
5. 状态、退款、符号候选及对应行数和金额。
6. 公司、时间、平台及其他可展示维度评估。
7. 推荐指标卡、图表和 ADS 粒度。
8. 数据质量风险、DIM 未匹配情况和待确认问题。
9. 来源批次店铺映射清单、未映射批次和源字段冲突。
10. 用户确认后的最终口径与验收基准。

报告最后生成下列交接清单，供 `$build-metric-pipeline` 直接使用：

```text
platform / metric_code / metric_name
source_tables / source_files / source_grain
formula / field_precedence / sign_rule
stat_date_rule / filters / fallback_rules
dimensions / chart_type / ads_grain
expected_rows / expected_date_range / expected_total
confirmed_decisions / remaining_questions
```

仅当 `remaining_questions` 为空时，标记“可以进入指标加工”。
