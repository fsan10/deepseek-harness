# 抖店订单报表下载

## 适用范围

使用指定抖音店铺 profile 的登录态，查询近 30 天下单时间，生成一次订单标准报表，等待历史报表可下载，
经验证后取得 ZIP，按短信解压密码解压并归档为标准报表“订单”。本流程不负责订单 ODS 导入，也不应与抖店
资金/结算账单流程混用。

## 前置条件

- 启动 `DY-抖音-MOCK咖啡旗舰店` profile；每次运行使用本次 `start_profile` 返回的 `wsEndpoint`。
- `platform/company/shop` 从 profile note 的键值读取，不凭店铺名或文件名推断公司。
- 先按 `$douyin-login-recovery` 检查登录态；深链回到 `/login/common` 时复用 profile 已保存的邮箱凭据、协议勾选和目标店铺选择。只有真实出现 `//*[@id="captcha_container"]/iframe` 才进入滑块人工接管等待，没有滑块直接继续。
- 确认本机 8770 服务已启用自动化验证码转发配置，令牌通过 `AUTOMATION_ROBOT_TOKEN`（兼容
  `INGEST_ROBOT_TOKEN`）提供；脚本会在触发短信前先探测服务和令牌，不可达时立即失败且不发送短信。
  不要把令牌、验证码或解压密码写入日志、状态文件或聊天。

## 标准流程

1. 运行 `douyin_order_download.py`，打开抖店订单页；若深链回到首页，点击首页“订单管理”进入新页面；根据 DOM 判断 A/B
   版本，有「展开」先展开。
2. 在“下单时间”区域优先使用页面快捷项。新版快捷项可能在日期弹层中；旧版则在日期范围右侧的独立下拉框中，
   该下拉框与日期框同级、宽度约 125px，打开后选择「近30日」（也兼容「近一个月/近1个月/近30天/最近30天」）。
   新页面输入框为 `开始范围/结束范围`，旧页面为 `开始时间/结束时间`。页面快捷项的实际口径是结束日往前 30 天，
   含结束日共 31 个日期；例如 2026-08-25 应显示 2026-07-26 00:00:00 至 2026-08-25 23:59:59。
   只有找不到快捷下拉/快捷项时才使用日期面板选择近 30 日。点击查询后等待列表请求和结果更新，等待有上限且不会重复点击查询。
3. 点击导出订单，选择“标准报表”，等待“请注意”弹窗完成渲染并点击其中的“确认”（旧版可能显示“确定”），确认弹窗消失后才认为任务创建成功。
   旧版弹窗通常是 `.auxo-modal-confirm`（外层可能为 `role="document"`），新版通常是
   `.aurora-modal.aurora-modal-confirm[role="dialog"]`，按钮是该弹窗内的
   `button.aurora-btn`；不要只查找某一个 ARIA role，也不要点页面上其他“确认”按钮。
   创建成功后立刻记录本地状态；后续任何失败都不能再次点击导出。若页面只在可见的短提示节点中返回
   “操作过于频繁/重复提交任务/5 分钟内不能重复生成”，将其视为已有任务，记录为已创建并直接复用导出记录；
   不得用整个页面正文或隐藏旧节点中的文字判断频控。
4. 打开“导出记录/历史报表”，监听 `/order/torder/queryDownloadStatus` 作为状态线索，但不能把 HTTP 200
   单独当成完成条件；必须在最新标准报表记录中看到匹配目标结束日期的“下载报表”按钮，按生成时间选择最新记录。
5. 用 Playwright 下载事件捕获 ZIP。下载验证不是必现分支：如果点击后先收到下载事件，直接保存 ZIP，
   不创建验证码 Challenge，也不要尝试寻找验证码输入框。只有检测到包含“下载验证/获取验证码”且有可见输入框的真实弹窗时，
   才创建 `verification_code` Challenge，点击「获取验证码」触发短信，等待负责人回复后填入验证码并确认；若已有未完成 Challenge ID，
   直接复用并禁止再次点击短信按钮。页面明确返回验证码错误时，向群里发送“上一次验证码输入错误，请重新输入”的新请求；最多重试三次，
   不重新生成订单报表。
6. ZIP 保存到工作目录后检查是否加密。加密时创建 `archive_password` Challenge；密码错误时先向群里发送
   “上一次解压密码输入错误，请重新输入”的提醒，再创建新密码请求；不重新生成或下载报表。非加密 ZIP 直接进入解压。
7. 安全解压并确保仅有一个 CSV/XLSX/XLS 报表文件，调用 `move_report.py` 归档到
   `C:\Users\win\Desktop\data\抖音\订单`；校验文件非空后才清理 ZIP、解压目录和完成状态。

## 执行命令

```powershell
& "C:\Users\win\AppData\Local\Programs\Python\Python312\python.exe" -m `
  scripts.auto_download.playwright.douyin_order_download `
  --cdp "<wsEndpoint>" --platform "抖音" `
  --company "舟益生物科技(南京)有限公司" --shop "MOCK咖啡旗舰店"
```

可选参数：`--work-dir` 指定可恢复工作目录，`--dest` 指定归档根目录，`--business-date` 指定文件日期前缀。
默认工作目录为目标根目录下 `.automation_cache\douyin_order\<店铺>`，默认归档根目录为
`C:\Users\win\Desktop\data`。

## 可恢复性与失败接管

- 状态为已创建导出任务时，重跑只打开历史报表并继续等待/下载，不重新创建任务。旧版本留下但没有确认凭据的
  `EXPORT_CREATED` 状态必须先在历史记录核验目标日期；找不到对应记录时清除该虚假状态，回到订单页重新查询并创建。
- 已有 ZIP 时，重跑直接请求解压密码并解压，不重新下载；状态文件同时保存验证码/密码 Challenge ID，进程中断、网络抖动或
  8770 重启后优先复用未完成的原请求。只有服务明确返回 Challenge 已过期/取消时才清除 ID。
- 下载验证弹窗已存在时，脚本不会重复点击下载按钮；验证码按钮为倒计时状态或状态文件已有 Challenge ID 时只等待现有挑战答案，
  只有创建新 Challenge 后才触发短信。
- 导出历史页先在当前页面轮询，约每 30 秒才刷新一次；刷新后若被带离历史页，会重新进入“导出记录”，避免 reload 丢失上下文。
- 飞书回复必须与当前 Challenge 类型匹配：验证码回复验证码，解压阶段回复原始解压密码。若机器人回复类型
  不正确，先检查 8770 服务是否已重载新代码，再清理本次测试产生的失效挑战，不能连续生成导出任务。
- 页面改版时优先检查当前 URL、导出记录卡片、可见弹窗和按钮文本，再修复选择器；不要用固定序号点击第一条
  “下载报表”。

## 验收标准

- 退出码为 `0`，归档目录生成非空的 `YYYYMMDD_抖音_公司_店铺_订单.<ext>` 文件。
- 导出记录的目标结束日期和最新生成时间与本次查询一致；没有重新生成重复任务。
- 验证码和解压密码分别创建、分别解析，ZIP 下载通过 Playwright 接管，解压密码错误不丢失 ZIP。
