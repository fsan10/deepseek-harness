# 指标加工与大屏设计

## 开始前

1. 定位包含本 Skill 的项目根目录。
2. 完整读取根目录 `AGENTS.md`。
3. 完整读取 `docs/ods_to_dws_to_ads_standard_flow.md`。
4. 读取 `$explore-ods-data` 生成的 ODS 指标探查报告和本轮用户确认结果。

## 进入加工的关卡

必须明确以下项目后才能修改文件或数据库：

- 平台、指标名、指标编码和业务定义。
- ODS 来源、最小粒度和公式字段。
- 字段优先级、文本解析、空值兜底和金额符号。
- 统计日期及兜底日期。
- 订单、售后、退款、结算等筛选。
- 公司/店铺映射规则和未匹配处理。
- 指标卡、配套图表、展示维度和 ADS 粒度。
- 当前数据的预期行数、日期范围和指标总额。

缺少任何会改变结果的项目时，先使用 `$explore-ods-data` 完成只读探查，并向用户提问。不得用默认经验替代业务确认。用户只要求方案时只输出方案，不实施。

## 图表与 ADS 决策

默认每个指标建立一张 ADS，同时服务一张指标卡和一张图：

- 指标卡：使用 ADS 指标字段求和，显示筛选范围内总值。
- 时间趋势：折线图；横轴 `stat_date`，纵轴指标金额，系列为平台或已确认分类。
- 分类比较：条形图；类别按指标降序，避免高基数标签。
- 费用或渠道构成：堆叠柱状图；只有类别不超过 5 且强调占比时才考虑饼/环图。
- 排名：横向条形图；保留 Top N 和“其他”需先获得用户确认。
- 比率：指标卡加时间趋势；ADS 同时保留分子、分母和比率，避免在 DataEase 重算口径。

财务 ADS 默认包含 `stat_date`、`platform_code/platform_name`、`company_code/company_name`。公司维度通过 `dim.dim_platform_shop_company` 左连接生成，未匹配数据写为 `unmapped` / `未匹配公司`。

## 分层实现

### ODS

- 现有 ODS 足够时只读，不重复建表。
- 新源文件没有 ODS 时，新增原始表和独立导入脚本，完整保留源字段及导入元数据。
- 导入必须幂等，记录批次、文件、原始行号、行哈希和入库时间；同平台、店铺、目标表和文件哈希的成功批次不得重复创建。
- 新建文件批次必须一次传入标准`shop_code`；公共Loader校验DIM并写入批次店铺上下文。
- ODS明细只保存`batch_id`，不得重复写入公司编码、公司名称或店铺公司关系。

### DWD

- 一个指标建立一张指标专属 DWD，表名包含平台、指标和明细粒度。
- 一行对应确认后的最小业务粒度。
- 只选字段、转换类型、解析日期金额、标准化符号、记录兜底来源。
- 保留状态字段和 ODS 追溯字段，不执行指标状态筛选。
- 必须通过`common.v_ingest_batch_shop_context`按`batch_id`获得标准店铺和`shop_identity_key`。
- 任一来源批次未映射或源店铺与批次店铺冲突时停止刷新，禁止平台唯一店铺、文件名或`default`静默兜底。

### DWS

- 为每个平台建立指标专属 DWS，表名包含平台、指标和汇总粒度。
- 在本层执行平台公式、状态筛选、退款规则和费用符号规则。
- 通常保留店铺日粒度，为 ADS 公司汇总提供上游数据。
- 保留纳入明细数、组成字段和来源更新时间，支持财务核对。

### ADS

- 一张 ADS 只服务已确认的指标卡和配套图表。
- ADS 只做 DIM 关联、统一字段、跨平台 `UNION ALL` 和图表粒度汇总。
- 平台特有清洗与筛选不得进入 ADS。
- 多个 ADS 必须使用一致的 `company_name` 和 `stat_date`，便于 DataEase 公共筛选器联动。

## SQL 与 ETL 要求

- 禁止在 `sql/` 根目录直接创建SQL文件。
- 平台ODS放入 `sql/<platform>/ods/`；平台DWD、DWS及刷新放入 `sql/<platform>/<metric_code>/`。
- 跨平台ADS及刷新放入 `sql/ads/<metric_code>/`；DIM放入 `sql/dim/`；通用对象放入 `sql/common/`。
- 新SQL使用项目最大序号继续全局递增，文件名包含动作或层级、平台、指标和粒度。
- ETL显式列出每个SQL的完整相对路径，不扫描整个目录，也不依赖文件名排序隐式执行。
- 使用显式 schema 和英文 `snake_case` 字段。
- 每张表添加 `COMMENT ON TABLE`，每个字段逐一添加 `COMMENT ON COLUMN`。
- 金额使用 `NUMERIC(18,2)`，业务日期使用 `DATE`，审计时间使用 `TIMESTAMPTZ`。
- 为主键、日期、公司和常用关联字段建立必要索引。
- 指标刷新默认在一个事务中使用 `TRUNCATE + INSERT`；失败全部回滚。
- Python ETL 使用项目连接环境变量，默认数据库为 `mock_coffice`。
- ODS导入命令必须显式包含`--shop-code`；影刀导入还应传`--shop-mapping-source robot_selected`。
- PowerShell 内联验证不得直接嵌入中文标识符，使用 Unicode 转义、参数化标识符或执行UTF-8 SQL文件。
- ETL 执行前校验来源表和必需字段，执行后打印各层行数、日期范围、组成金额和最终总额。
- 保留用户已有修改，不改动无关对象，不通过修改 ODS 修正结果。

## 实施顺序

1. 清理或替换同一指标的废弃指标层对象，不删除 ODS 数据。
2. 建立或更新必要 DIM，种子数据不得覆盖后续人工维护。
3. 新建 ODS（仅新来源需要）、DWD、DWS、ADS 建表 SQL。
4. 新建对应刷新 SQL 和一键 ETL。
5. 更新 `AGENTS.md`（仅规则变化时）和标准流程文档中的指标示例。
6. 在 `mock_coffice` 实际执行，至少连续刷新两次验证幂等。
7. 输出 DataEase 数据集、指标卡、图表和公共筛选器配置。

## 验收

必须完成并报告：

- ODS 与 DWD 最小粒度行数、重复数和追溯关系。
- 至少 5 条公式抽样，包含正常、兜底、退款/冲回或零值场景。
- DWS 纳入/排除数量、组成金额及公式重算结果。
- ADS 主键唯一、日期范围、公司映射命中和 `unmapped` 数量。
- DWS 按 ADS 粒度重算与 ADS 的双向差异为 0。
- 最终金额等于探查报告中用户确认的基准值；不一致时停止并诊断，不能改口径凑数。
- 新增表全部有表注释，全部字段有字段注释。
- DataEase 指标卡总额与 ADS 一致，图表各点之和与指标卡一致。

## 完成交付

最终说明应包含：

1. 指标公式、日期、筛选和符号口径。
2. ODS、DWD、DWS、DIM、ADS 的表名与粒度。
3. 一键刷新命令。
4. DataEase 数据集、指标字段、图表字段和公共筛选字段。
5. 实际验收行数、日期范围、组成金额、总额和未匹配公司数量。
6. 关键文件链接和仍为预留值的数据来源。
