## 2. "9 月禧饮数据不对"的逐层定位

### 2.1 系统里真实存在的三套数字

| 口径 | 收入 | 支出 | 净额 | 数据源 |
|---|---:|---:|---:|---|
| **纯结算（月报）** | 136,217.40 | 62,790.10 | 73,427.30 | `ads.ads_settlement_net_company_shop_monthly` |
| **经营（ADS/经营流水）** | 133,806.50 | 61,377.73 | 72,428.77 | `ads.ads_platform_main_business_income_...` / `..._expense_...` |
| **您期望的** | 133,806.50 | 60,379.20 | 73,427.30 | —（系统当前无此口径） |

分解说明：

- 纯结算收入 136,217.40 = 收入组成（订单实付 + 补贴），**未减退款**；
  纯结算支出 62,790.10 = 61,032.08（费用）**+ 1,758.02（订单退款）**（"订单退款"是结算指标的支出类型之一）。
- 经营收入 133,806.50 = 136,217.40 − 1,758.02 − 652.88（两笔退款均冲减收入）；
  经营支出 61,377.73 = 61,032.08 + 345.65（资金费用净额）；
  经营净额 72,428.77 = 133,806.50 − 61,377.73。
- **两口径净额差 = 73,427.30 − 72,428.77 = 998.53 = 资金退款 652.88 + 资金费用净额 345.65**（恒等式）。

### 2.2 您期望数字的算式还原

```
收入 133,806.50 = 136,217.40 − 1,758.02 − 652.88        ✓（系统已实现）
支出  60,379.20 =  62,790.10 − 1,758.02 − 652.88        （您期望，系统未实现）
净额  73,427.30 = 133,806.50 − 60,379.20                （与结算净额相同）
```

或等价地：`支出 60,379.20 = 61,032.08（结算费用） − 652.88（资金退款）`。

### 2.3 差异拆解（为什么系统给的是 61,377.73）

```
61,377.73（系统经营支出）
− 60,379.20（您的期望支出）
= 998.53
= 652.88（资金退款：现在冲减收入）
+ 345.65（资金费用净额：现在计入支出）
```

**换句话说：您期望的支出 = "结算费用"再减去"资金退款 652.88"。**
从数学等式看，`133,806.50 − 60,379.20 = 73,427.30` 成立（因为两端同减、互相抵消）；
但从业务含义看，"支出"这一栏并不包含 652.88，把它当减项意味着**同一笔资金退款被使用了两次**：
- 收入侧：652.88 冲减收入 ✓（有业务含义：退款使收入减少）
- 支出侧：−652.88 是"凭空减"（结算费用 61,032.08 里没有这笔钱）

净额的后果：**资金真实流出 998.53（退款 652.88 ＋ 资金费用 345.65）被从净额里抹掉，剩余净额 73,427.30 变成"纯结算净额"（平台应结算金额），不再是"扣除全部资金流出后的经营净额"。**

### 2.4 关于"费用公式是否重复计算了退款"

逐项核验的结论（针对您的三个疑问）：

1. **"之前费用公式没有减去这两个（退款）"** —— 不成立：
   - 两个退款都已作为"收入冲减"生效（−1,758.02 与 −652.88 都在收入 133,806.50 里）；
   - "费用"里本来就不含"资金退款 652.88"（它只在收入侧），所以"费用需要减去它"没有对象。
2. **"费用公式重复计算了退款"** —— 当前实现的费用（61,032.08 + 345.65）中**没有任何退款成分**，不存在重复。
3. **唯一"含退款"的支出是"纯结算月报"的 62,790.10**（其中"订单退款 1,758.02"计在支出侧）——这是结算指标（`dws_ks_settlement_*`）的原始设计。若要把"订单退款"从支出挪到收入侧（对齐您的口径），**合法的操作只应调整 1,758.02**：
   - 月报收入 → 134,459.38（136,217.40 − 1,758.02）；月报支出 → 61,032.08（62,790.10 − 1,758.02）；净额不变 73,427.30。
   - **若再对 652.88 做同样处理，就超出"结算口径"的边界**：652.88 从未出现在任何一支的支出里，从支出中减它属于"重复冲减"——净额等式仍成立（两端抵消），但"支出"不再代表费用，且净额不再反映资金的真实流出（见 2.3）。
4. 系统最高层文档（`docs/operating-finance-source-reconciliation.md`）已明文规定：
   > "资金退货款冲减收入，佣金/服务费返还冲减费用；**不能为匹配目标金额重复冲减**。"
   
   您的"60,379.20"正是"为同时保持收入 133,806.50 与净额 73,427.30 而做的重复冲减"结果。**建议：先与财务口径确认"支出"到底要哪一种展示**（见第 5 节），而不是直接改公式。
