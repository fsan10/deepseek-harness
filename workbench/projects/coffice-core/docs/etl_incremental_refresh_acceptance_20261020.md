# 文件导入增量刷新优化与验收（2026-10-20）

已完成代码优化，并使用用户提交的57个快手文件进行了真实导入、正式刷新、全量回滚对照和范围外数据校验。原始ODS批次全部保留。

**采用的方案**

文件导入按“标准平台、标准店铺、受影响的业务月份”刷新DWD、DWS和ADS。月份来自实际业务日期与可信报表覆盖范围；补导历史数据会重算对应历史月。重复文件不重复计算，同一导入会话复用同一刷新任务。

来源先按既有来源选择规则生成一次事务内快照，再供各指标复用；保留来源防重、批次店铺映射和金额公式校验。冻结批次上界并排除当时尚未成功的较早批次，防止并发导入在后续节点混入新的来源。

首次按可信下载回执补登记覆盖范围时，会更新事务内来源缓存，使同一轮刷新立即采用已核验的范围，避免旧缓存再次触发来源重叠校验。

月度排名及环比会联动重算下月并读取上月，公司的汇总保留其他店铺贡献；推广费零值行保留跨平台日期日历。失败回滚，不自动退回全量。文件导入阶段跳过持久化建表、改表和安装脚本，避免重复安装引起表锁。

全量刷新仅允许人工创建，定时创建和执行两端均拒绝。人工全量沿用原安装和重建流程；银行财务提交保留原有受控入口。新增迁移467_incremental_etl_context_postgres.sql已应用到当前数据库。
