# 天猫宝贝销售明细报表替换订单源 ODS 探查报告

## 1. 探查目标与边界

- 平台：天猫。
- 新标准源文件：`data/天猫/订单/天猫订单6.25-7.5销售明细表+退款状态+退款金额.xlsx`。
- 目标：后续天猫订单均使用宝贝销售明细报表，并把ODS业务字段精简为当前指标真正使用的最小集合。
- 约束：继续使用现有规范表名`ods.ods_tmall_order_raw`，现有DWD、DWS和ADS表名尽量保持不变。
- 本轮仅做源文件、数据库和现有指标链路的只读探查，不修改SQL、ETL、表结构或业务数据。
- 本报告金额单位均为元，日期均为自然日。

## 2. 结论摘要

重新导出的文件已解决上一版销售明细的覆盖缺口：

| 项目 | 探查结果 |
| --- | ---: |
| 源数据行数 | 1,098 |
| 唯一子订单数 | 1,098 |
| 唯一主订单数 | 558 |
| 子订单重复数 | 0 |
| 子订单/主订单缺失数 | 0 / 0 |

| 有效商品行商家编码缺失 | 0 |

因此，新报表可以作为天猫订单的长期标准来源，并能够支持：

- 天猫GSV；
- 天猫达人GMV、退款和达人数量；
- 天猫达人佣金补零日期；
- 天猫运营GMV、退款、订单数、件单价；
- 天猫统一产品GMV占比。

但是不能把新文件直接插入旧主订单ODS结构。正确方案是保留`ods.ods_tmall_order_raw`这个表名，把业务字段精简为13个必要字段并迁移到子订单粒度，同时调整现有SQL/ETL内部字段引用和去重逻辑。

## 3. 精简ODS字段与最小粒度

### 3.1 最终保留的13个业务字段

当前天猫GSV、运营成交、达人业绩、达人佣金补零和产品占比使用以下13个业务字段：

| ODS业务字段 | 使用场景 | 必要原因 |
| --- | --- | --- |
| 子订单编号 | 全部指标 | ODS最小粒度和最新版本去重键 |
| 主订单编号 | 运营、达人、订单数 | 主订单去重、刷单整单排除 |
| 商品标题 | 运营、达人 | 识别`MOCK推荐官`、独立赠品和达人专属/推荐标题 |
| 购买数量 | 运营 | 成交件数和成交件单价 |
| 商品属性 | 产品占比 | 识别组合编码中“赠”字后的赠品组件 |
| 订单状态 | GSV、退款、达人 | `交易关闭`判断 |
| 商家编码 | 产品占比 | 映射公司统一产品和分类 |
| 买家应付货款 | 运营、达人 | 商品行GMV、退款、刷单判断 |
| 买家实付金额 | GSV | 天猫GSV金额 |
| 退款状态 | GSV | 用户确认的售后状态字段，排除`退款成功` |
| 退款金额 | GSV审计 | 核对退款成功行，不直接从GSV扣减 |
| 订单创建时间 | 运营、达人、佣金补零 | 运营自然日和达人自然日 |
| 订单付款时间 | GSV | GSV日期，缺失时创建时间兜底 |

ODS继续保留7个公共审计字段：

```text
id
batch_id
source_file_name
source_sheet_name
source_row_no
row_hash
ingest_time
```

最终`ods.ods_tmall_order_raw`共20个字段：7个公共审计字段加13个业务字段。

### 3.2 不进入精简ODS的其他源字段

以下字段当前任何天猫订单指标都不使用，不进入精简ODS：

```text
商品价格
支付单号
商品ID
分阶段信息
备注标签
商家备注
发货时间
物流单号
是否主动赔付
主动赔付金额
主动赔付出账时间
应发货时间
免单资格
免单金额
确认收货时间
```

删除原因：

- 商品GMV已经改为`买家应付货款`，不再使用`商品价格`。
- 退款已经固定使用`订单状态='交易关闭'`时的同口径GMV，不直接使用源`退款金额`。
- 商品归属只使用公司商家编码，不使用平台`商品ID`。
- 支付单号、履约、物流、备注、赔付和免单字段不参与现有指标、筛选器或图表。
- 后续确有新指标需要时，再通过新DDL追加字段并从对应新批次开始采集。

### 3.3 粒度与业务键

- ODS最小粒度：一行一个天猫子订单。
- 稳定业务键：`标准店铺编码 + 子订单编号`。
- 主订单关系：一个主订单对应一个或多个子订单。
- 本文件1098个子订单全部唯一，归属558个主订单。
- 558个支付单号全部唯一，当前与主订单一一对应，但支付单号只适合做校验，不应代替子订单业务键。
- 后续重叠日期导出可能重复包含同一子订单，ODS保留所有原始批次，各指标DWD按`shop_code + 子订单编号`选择`ingest_time/id`最新版本。

## 7. 天猫GSV重算

### 7.1 2026-07-29修订口径

```text

GSV = 子订单买家实付金额之和
WHERE 子订单状态 <> '交易关闭'
  AND 退款状态 <> '退款成功'
```

## 9. 产品GMV映射与占比

### 9.1 处理规则

1. 排除`MOCK推荐官`和标题包含`赠品勿拍`的独立辅助行。
2. 产品GMV直接取子订单`买家应付货款`，不乘购买数量。
3. 商家编码把全角加号统一成半角加号后按`+`拆分。
4. 商品属性包含“赠”时，只保留“赠”字前对应的付费编码组件。
5. 组合装按编码末尾数量分摊买家应付货款，最后一个组件吸收分币差。
6. 通过`dim_company_product_code_mapping -> dim_influencer_product -> 二级分类 -> 一级分类`取得展示归属。
7. 购物金编码`A1`、`C3`固定归入`非商品 -> 购物金 -> 购物金`。
8. 买家应付货款为空或0的商品行不产生产品GMV。

### 9.2 编码质量

- 598个有效商品行的商家编码缺失数为0。
- 558个正GMV商品行共产生741个付费编码组件。
- 741个组件分摊金额合计64,891.08元，与有效商品行GMV完全一致。
- 按当前商品DIM及购物金单列规则，未映射付费组件为0。

特殊编码：

- `A1`、`C3`：购物金，建议归为`非商品 -> 购物金 -> 购物金`。
- `M-TZ`：只在组合规格“赠”后的贴纸赠品中出现，不进入付费产品分摊。
