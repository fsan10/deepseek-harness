# 视频号、京东、快手、小红书、拼多多运营成交指标与图表 ODS 探查报告

## 1. 业务目标

- 指标：总成交额 GMV、总退款、退款率、成交总订单数、成交件单价。
- 平台：视频号、京东、快手、小红书、拼多多。
- 图表：各平台 GMV 占比、流量结构及其 GMV 占比、各产品销售额 GMV 占比。
- 产品展示层级：`一级分类 -> 二级分类 -> 公司统一产品名称`。
- 展示数据集：继续扩展抖音运营成交的三张 ADS，与抖音共用公司、日期、平台和店铺筛选器。
- 已确认的抖音口径继续作为跨平台语义：
  - GMV 取平台订单商品行的商品原价/单价，不扣平台或商家补贴，不使用财务 GSV。
  - 不按订单状态或售后状态筛选。
  - 整个订单的应付/实付金额达到 2,000 元时，按订单整单排除。
  - 赠品组件仍解析、映射并保留审计，但不进入产品 GMV；组合装按付费组件数量权重拆分商品行 GMV。
  - 成交总订单数按非刷单订单号去重。
  - 成交件数只累计商品行 GMV 大于0的商品数量，成交件单价为汇总 GMV 除以汇总件数。

| 小红书 | `商品总价(元)` | `用户应付金额(元)` | `订单创建时间` | `商家编码` | `SKU规格` |
| 拼多多 | `商品总价(元)` | `用户实付金额(元)` | `订单成交时间` | `商家编码-规格维度` | `商品规格` |

选择理由：

- 视频号和快手存在明确的商品单价字段，直接等同抖音商品单价语义。
- 京东的 `京东价` 是商品行原价，`订单金额`、`应付金额`和`商家应收`会受到订单金额、优惠或系统参考状态影响。
- 小红书和拼多多没有独立商品单价字段，`商品总价(元)`是当前最接近“商品行原始销售额”的字段；不改用优惠后的用户应付或商家实收。
- 数值清洗统一清除首尾空白、千分位和币种符号。快手金额全部带 `¥`，清除币种符号后 1,378 行均可解析。

候选计算公式：

```text
平台 GMV = SUM(商品行原价)
WHERE 订单不属于任一商品行订单应付/实付金额 >= 2000 的刷单订单

成交总订单数 = COUNT(DISTINCT 非刷单订单号)
成交件数 = SUM(CASE WHEN 商品行原价 > 0 THEN 商品数量 ELSE 0 END)
成交件单价 = GMV / 成交件数

产品 GMV = 正 GMV 商品行按付费商家编码组件数量权重分摊后的金额
```

不增加订单状态或售后状态筛选。

## 6. 产品编码、组合装和赠品

产品归属继续使用：

```text
一级分类
  -> 二级分类
  -> dim.dim_influencer_product
  -> dim.dim_company_product_code_mapping
  -> 各平台商家编码组件
```

处理规则：

1. 将全角加号统一为半角加号，按原顺序拆分商家编码。
2. 商品规格含“赠”时，“赠”字前对应的组件为付费组件；后续赠品组件仍保留、识别和映射，但分摊GMV为0。
3. 无“赠”时，全部编码组件均为付费组件。
4. 按编码数量后缀计算权重，最后一个付费组件吸收分币差。
5. 快手和视频号等来源存在历史缩写编码。这些缩写是全公司编码别名，在公司级DIM统一解析，不形成平台商品身份：
   - `nHB -> M-MHB-n`
   - `nTZ -> M-TZ-n`
   - `nFB -> M-MFB-n`
   - `nLH -> LH-n`
   - `nBXTD -> M-BXT-D-n`
   - `nBXTF -> M-BXT-F-n`
   - `nSY -> M-NXSY-n`
   - `nSYD -> M-NXSY-XD-n`
   - `nMG -> M-MGNT-n`
   - `nMGD -> M-MGNT-XD-n`
   - `nML -> M-MLXY-n`
   - `nMLXYD -> M-MLXY-XD-n`
6. 以上历史缩写均有商品规格和标准编码样本互相印证；归一后仍通过可维护DIM获取稳定商品ID、公司商品编码、分类和产品名，不在DWS硬编码商品归属。

### 三张共享 ADS

- DWD：每个平台独立运营成交商品行明细，保留全部订单状态和售后状态，不提前筛选。
- DWS订单行：在平台层执行刷单整单排除、退款代理值、成交件数和流量标准化。
- DWS产品分摊：拆分并保留全部编码组件，统一解析编码与数量，标记赠品并按付费数量分摊金额。
- `ads.ads_operating_sales_company_shop_daily`：公司店铺日平台粒度，服务5张指标卡和各平台 GMV 占比。
- `ads.ads_operating_sales_traffic_company_shop_daily`：公司店铺日、流量体裁、流量渠道粒度。
- `ads.ads_operating_sales_product_company_shop_daily`：公司店铺日三级产品粒度。
- 产品 ADS 粒度：

```text
stat_date
+ platform_code / platform_name
+ company_code / company_name
+ shop_code / shop_name
+ large_product_category
+ product_category_l2
+ product_name
```

- DataEase 指标卡：`SUM(gmv_amount)`、`SUM(refund_amount)`、`SUM(refund_amount)/SUM(gmv_amount)`、`SUM(transaction_order_count)`、`SUM(gmv_amount)/SUM(sold_unit_count)`。
- 平台 GMV 占比：类别`platform_name`，指标`SUM(gmv_amount)`。
- 流量结构：层级`traffic_content_type -> traffic_channel`，指标`SUM(gmv_amount)`。
- 产品 GMV 占比：层级`large_product_category -> product_category_l2 -> product_name`，指标`SUM(gmv_amount)`。
- 公共筛选：`company_name`、`stat_date`、`platform_name`、`shop_name`。

## 9. 数据质量风险与待确认项

1. 京东没有售后状态字段；用户已确认订单状态以`(删除)`开头的商品行计为京东退款，当前退款基准为1,378.00元。
2. 小红书和拼多多没有稳定流量两级字段，只能如实展示为`未提供`。
3. 当前五个平台均只有一个成功订单批次。用户后续会提供新的显示店铺编码；新批次必须显式提供`shop_code`，并重新检查重复版本和源店铺冲突。
4. 快手历史缩写规则只做编码格式归一，不维护产品名称或分类；产品分类变更仍由后台 DIM 控制。
5. 当前五个平台付费组件在上述清洗后均能命中产品 DIM，没有未映射 GMV。
